# MySQL Benchmark — pure-Rust ANTLR runtime (`antlr-rust-runtime`)

This target runs the MySQL benchmark on
[`antlr-rust-runtime`](https://github.com/ophi-dev/antlr-rust-runtime), a
pure-Rust ANTLR v4 runtime + code generator (no JVM or C++ runtime dependency).
Both the `Cargo.toml` dependency and the checked-in recognizers under
`src/generated/` are **v0.12.0** — the `// @generated by antlr-rust-runtime
v0.12.0` header on those files matches the runtime version used to build the
target, so regeneration stays reproducible.

## Prerequisites

A Rust toolchain (install via <https://rustup.rs>). Nothing else — the ANTLR
runtime is a normal crates.io dependency.

## Build & run

```bash
./build.sh                      # cargo build --release
./target/release/mysql-benchmark
```

The runner reads the shared fixtures from `../../data` (override with
`MYSQL_BENCH_DATA=/path/to/data`).

## Methodology (identical to the C++/TS targets)

- Split each file on `$$$`; per statement, time `tokenize` (re-feed the
  long-lived lexer and fill its token stream) then `errorCheck` (reset the
  long-lived parser and parse those same tokens **without** building the CST).
  This matches the reference `ParseService` lifecycle.
- 1 cold run + 5 warm runs; warm result drops the 2 slowest of the 5 and averages
  the rest.
- Output per file: `lexing ⧸ parsing ⧸ sum` in milliseconds.

**Cold vs warm / the learned DFA:** the cold pass calls `clear_dfa()` on the
reused lexer and parser before each file, matching the reference targets'
`clearDFA()` calls. Warm passes retain learned state. The whole run executes on
one worker thread with a generous stack.

## Target-specific code (the base-class port)

The official Oracle MySQL grammar is target-coupled: it drives 246 semantic
predicates and 41 lexer custom actions through `MySQLBaseLexer` /
`MySQLRecognizerCommon` base classes. This target ports those base classes into
the runtime's `SemanticHooks` trait:

- `src/hooks.rs` — `MySqlHooks: SemanticHooks`: `determineFunction`,
  `determineNumericType`, `emitDot`, the `||`/`NOT` mode ternaries, `checkCharset`,
  version-comment state, and the two stateful lexer predicates
  (`checkMySQLVersion`, `inVersionComment`).
- `build.rs` — reads the generator's `semantics.json` manifests and precomputes
  the 124 pure `serverVersion`/`sqlMode` predicates to `const` tables at the
  benchmark's fixed `serverVersion = 80400`, `sqlMode = ANSI_QUOTES`.
- `src/generated/` — the lexer/parser generated by `antlr4-rust-gen` from the
  grammar `.interp` + `.g4` (with `--sem-unknown hook`), plus the two
  `*_semantics.json` manifests `build.rs` consumes.

Regenerate the parser (needs `antlr4-rust-gen`, shipped with the runtime):

```bash
antlr4-rust-gen --lexer  MySQLLexer.interp  --grammar MySQLLexer.g4 \
    --sem-unknown hook --allow-unsupported-lexer-actions --out-dir src/generated
antlr4-rust-gen --parser MySQLParser.interp --grammar MySQLParser.g4 \
    --sem-unknown hook --out-dir src/generated
# copy each out-dir's semantics.json to lexer_semantics.json / parser_semantics.json
```

## Correctness

All three fixtures parse with **zero** syntax errors at `serverVersion = 80400`,
`sqlMode = ANSI_QUOTES`: `statements.txt` 922/922, `bitrix_queries_cut.sql`
530/530, `sakila-data.sql` 57/57.
